## 1. Архитектура выбранной IDE (Visual Studio Code)

Visual Studio Code построен на базе Electron. Пользовательский интерфейс редактора работает в отдельном UI-процессе, а расширения выполняются в процессе Extension Host. Такое разделение изолирует код расширений от основного интерфейса IDE: ошибка или высокая нагрузка в расширении не должны напрямую блокировать отрисовку окна редактора.

Extension Host предоставляет расширениям программный интерфейс VS Code API. Через него плагин может получать активный редактор, документ и выделение, показывать Quick Pick, регистрировать команды и выполнять изменения текста.

### Точки расширения

Основные точки расширения описываются в `package.json`:

- `activationEvents` содержит событие `onCommand:case-converter.convertStyles`, по которому загружается расширение;
- `contributes.commands` регистрирует команду `case-converter.convertStyles` с названием **Convert Styles**;
- поле `main` указывает скомпилированный входной файл `out/extension.js`.

### VS Code API и LSP

Плагин использует VS Code API для работы с документом и командой. Для безопасного поиска идентификаторов используются семантические токены, предоставляемые языковым сервером через механизм Language Server Protocol.

Сначала расширение получает легенду токенов, то есть соответствие числовых индексов и типов. Затем запрашивается массив Semantic Tokens. Из него выбираются только токены типов `variable`, `parameter` и `property`. Благодаря этому обычные слова, строки, комментарии, внешние вызовы функций и библиотечные имена не становятся объектами массового переименования.

## 2. Краткое техническое задание проекта

### Цели

1. Реализовать команду VS Code для пакетного преобразования имен переменных.
2. Поддержать стили `snake_case`, `camelCase` и `PascalCase`.
3. Сохранить корректность замен как для всего документа, так и для выделенного фрагмента.
4. Ограничить область изменений идентификаторами, распознанными языковым сервером.

### Поддерживаемые типы данных

- `NamingStyle` — перечисление доступных стилей именования;
- `IdentifierType` — тип идентификатора (`variable`, `function_call`, `property`);
- `VariableToken` — объект с именем, стилем, типом и позициями идентификатора;
- `Set<string>` — множество известных имен для быстрого поиска;
- массив Semantic Tokens — данные от языкового сервера, представленные в VS Code API как `Uint32Array`.

### Ограничения безопасности

Плагин не изменяет произвольные совпадения текста. Перед заменой имя должно одновременно присутствовать в `Set<string>` семантически найденных имен и соответствовать одному из поддерживаемых шаблонов. Внешние функции, библиотечные вызовы и текстовые значения не переименовываются.

Все изменения выполняются одним вызовом `editor.edit`. Это позволяет VS Code применить операцию как единую транзакцию и отменить ее стандартной командой Undo.

## 3. Архитектура плагина и блок-схема

Проект разделен на два основных модуля.

### `extension.ts` — интеграция с IDE

Модуль отвечает за жизненный цикл расширения и взаимодействие с VS Code:

- регистрирует команду;
- получает активный редактор и документ;
- фиксирует `Selection` до открытия Quick Pick;
- вычисляет `baseOffset` для выделенного фрагмента;
- получает Semantic Tokens;
- вызывает функции лексического ядра;
- создает и применяет набор замен через `editor.edit`.

### `converter.ts` — лексическое ядро

Модуль не зависит от интерфейса редактора и отвечает за обработку имен:

- разбивает имена на слова;
- собирает их в выбранном стиле;
- определяет исходный стиль регулярными выражениями;
- извлекает идентификаторы из текста и сохраняет их позиции.

### Блок-схема процесса

```text
Запуск команды case-converter.convertStyles
                |
                v
Получение activeTextEditor
                |
                v
Сохранение Document, Selection и baseOffset
                |
                v
Выбор нового стиля через Quick Pick
                |
                v
Получение Semantic Tokens и их Legend
                |
                v
Фильтрация типов variable, parameter, property
                |
                v
Создание Set<string> известных имен
                |
                v
extractVariables(text, knownVariables)
                |
                v
Проверка стиля и позиций каждого VariableToken
                |
                v
Сортировка токенов по posStart в обратном порядке
                |
                v
convert(token.name, newStyle)
                |
                v
Единая транзакция editor.edit с replace
                |
                v
Сообщение о результате пользователю
```

### Структуры данных и сложность

`Set<string>` хранит имена, полученные из Semantic Tokens. Проверка `knownVariables.has(word)` в среднем выполняется за `O(1)`, поэтому фильтрация найденных слов не требует полного последовательного поиска по списку.

`VariableToken[]` содержит результат лексического анализа. Каждый элемент хранит имя, исходный стиль, тип идентификатора и полуинтервал позиции `[posStart, posEnd)`. Позиции позволяют сформировать точный `vscode.Range` для замены.

Semantic Tokens передаются VS Code API как `Uint32Array`. Данные закодированы группами по пять чисел:

```text
[deltaLine, deltaStartChar, length, tokenType, tokenModifiers]
```

`deltaLine` и `deltaStartChar` являются относительными смещениями, поэтому при обходе массива вычисляется абсолютная строка и позиция символа каждого токена.

Обратная сортировка токенов нужна для сохранения исходных позиций при замене имен разной длины. Сначала изменяются самые правые участки текста, поэтому смещение слева не влияет на уже подготовленные диапазоны справа. Все операции при этом передаются в один `editor.edit`.
